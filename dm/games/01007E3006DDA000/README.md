# Kirby Star Allies (`01007E3006DDA000`)

<!-- PEANUTS: a Peanuts Native profile and note (Banana Native has none for this title). -->

Update 4.0.0a (v393216) on base 1.0.0. SDK 4.4.1. HAL Laboratory's own engine on NintendoWare (G3d, Font, Ui2d, Vfx, Atk) with NVN graphics: the same engine family as [Kirby's Return to Dream Land Deluxe](../01006B601380E000/README.md) and [Kirby and the Forgotten Land](../01004D300C5AE000/README.md), several SDK versions older. Modules `main`, `subsdk0` (NintendoSDK_movie, the MP4 movie module) and `sdk`.

**Status (current): plays on Android, at 60 fps on Turnip.** On an AYN Thor (Snapdragon 8 Gen 2, Adreno 740, Android 13), 2026-11-28, with the host changes this profile depends on (igawa6/peanuts-native#962, the movie; igawa6/peanuts-native#963, the frame rate row): the opening movie in colour, the file select, the main menu, World 1's first stage played through to its boss (Mr. Frosty) and the fight, with fire and ice abilities and three CPU friends; the ground under fire and ice effects draws black (Open). Turnip 27.0.0-R2: 60 fps in the stage and the boss fight (59.6 to 59.8 over 60-frame windows, 16.8 ms a frame), memory peak 3.93 GB (the game process's VmHWM). Qualcomm's driver (the system driver): the same stage at 30 fps (the GPU at about 15 ms a frame; 60 in the menus), memory peak 3.50 GB. No crash and no `[RED]` line from the game in either run. Only the 60 cap (the default) was measured; 30 and 20 are experimental (Open). Not run on the Mac.

## Frame rate

The game paces itself in whole vsyncs: an interval index at `[main+0x54c5b0]+0` selects the vsyncs a frame from the table at `main+0x3b5ac8` (1, 2, 3, 4, 5, 6); `main+0x5a48` is its setter. Reviewed from the [FPSLocker Warehouse config for this build](https://github.com/masagrator/FPSLocker-Warehouse/blob/v4/SaltySD/plugins/FPSLocker/patches/01007E3006DDA000/D55608916FA56C18.yaml) (interval offsets found by Kirby567Fan): `fpslocker … vsync_index_u32` writes 60 / fps − 1 and `fpslocker_plan … m0x5a4c` makes the setter's store a `NOP`. The launcher offers Game owned (the default, 60), 60, 30 and 20 (`fps_modes 20,30,60`, `fps_limit_present 1`). Above 60 is not possible this way: no index gives half a vsync. The config's "remove double buffer" writes are not taken, as the host presents the frames itself.

- **Measured:** 60 (the default) on Turnip 27.0.0-R2, above. **Experimental:** 30 and 20 (`fps_limit_present 1`): on Turnip 27.0.0-R3 (2026-11-24) the game kept its normal speed at 30 by eye, with no timed walk; 20 was not tried.
- The in-game panel's live cap does not move this game's rate: the index is written from the launcher's pick at the start (`present cap 30 fps not applied` in the log when the panel sets it); pick the cap before starting the game.

## Found on this game

- **Resolved: the opening movie drew black, its sound playing.** (the host's `nv12-colorspace` key, igawa6/peanuts-native#962) The game's movie player (`main+0x1529d8`) reads `nv12-colorspace` from the decoder's output format and picks its YUV → RGB matrix by it (1 BT.601 limited, 2 BT.601 full, 3 BT.709 limited, 4 BT.709 full). The host did not set the key, `FindInt32` left 0, and the player's default matrix is all zeros. The host now sets it from the decoder's declared colour space (`md_colorspace` in `dm/host/hle_movie.c`), BT.709 limited for this 1080p H.264.

## Open

- **Current, open: fire, ice and freeze effects draw black patches on the ground** (Turnip and Qualcomm's driver alike). The decals (`BurntMark`, `IceMark`, `FreezeMark`; pixel shaders `5d25056afde19d3a`, `5d14614a5b917f71`, `c499eb047397ba82`) load the G-buffer texel as `r32ui` / `rg32ui` words, blend and store it back; the replay views those images in the texture's own channels (RGBA8 as RGBA8_UINT), so three channels read 0 and the decal writes black. Viewing them in the declared word format fixes the picture on Turnip, but on Qualcomm's driver the images remade with R32_UINT / R32G32_UINT in their format list draw the whole frame as repeated vertical strips, so that change is not in yet.
- **Frame rate caps 30 and 20:** not timed (the median and slowest frame and 10 game seconds against 10 s); experimental until they are.
- **Qualcomm's driver runs the stage at 30:** the GPU takes about 15 ms a frame there against 9 on Turnip; not looked into.
- **Memory rows:** the survey's guess; the measured peaks are above.
- **Later worlds, the other modes (Guest Star, Chop Champs, Star Smash) and saves over several sessions:** not played.
- **`[RED] vk: uniform buffer at … is not in placed guest RAM`** (once a run, then `is not readable: it reads zeros` once): nothing wrong was seen on screen; which draw reads it is not checked.
- **Prewarm keys:** `vk_pipelines.keys` from fresh-cache runs on each driver are not attached yet.
