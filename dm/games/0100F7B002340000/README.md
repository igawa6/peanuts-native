# FIFA 18 (`0100F7B002340000`)

<!-- PEANUTS: a Peanuts Native profile and note (Banana Native has none for this title). -->

Base game 1.0.0 (v0), no update tested. SDK 3.4.0, NVN. EA's FIFA engine for the Switch (EA basekit: AssetStream, the RNA renderer `fifarna`, Apt UI, EAThread). Modules `main`, `subsdk0` (NVN's GLSLC, which `main` imports but never calls: `nn::gfx::detail::GlslcDll` is linked and unused) and `sdk`. The RomFS ships `fifazf.nss`, an unstripped ELF of `main` (symbols and DWARF), which makes every crash report and every disassembly readable by name.

**Status (current): plays on Turnip; on Qualcomm's system driver, matches play but replays, celebrations, training and close-up camera views do not.** On a Retroid Pocket 6 (Adreno 740) it boots, shows the menus with their text, and plays whole matches at 60 fps at 1080p (docked mode; GPU about 10 ms a frame), with the players, crowd, shadows and rain right, on Qualcomm's system driver 0676.53. On Turnip T30 (`DM_VK_DRIVER`) the replays, celebrations, training, the goalkeeper camera and the kit preview's faces are right as well (run on the build before the rebase onto the current main, which still had its own glyph-cache fix; see below). Not checked: handheld mode (720p), the Mac, a companion.

## Files and shaders

- RomFS: EA BIG4 archives (`data0` … `data7`, `datax`, one per language, with `.bh` tables beside them). Their members are chunk-compressed (`chunkzip`, `chunzstd`); `datax.big`'s are also EASF-encrypted.
- **Current:** 330 shaders (160 vertex, 160 pixel, 10 compute) from 189 NXSHADER effects (`.fxo`: an `NXSHADER` header and one whole GLSLC output each, a vertex + pixel program or a compute one) in `data/fifarna/shader.big` and `shaderboot.big` inside `datax.big` → [NXSHADER effects in EA BIG4 archives behind EASF and chunkzip](#found-on-this-game). All 330 translate and pass `spirv-val`.

## Found on this game

- **Resolved: no shader container found.** `shader_split.py` reads EA BIG4 archives (`eabig.py`, `ea_big_shaders`): the archive's table, then only members named `.big` or `.fxo`, through EASF and chunkzip. EASF is AES-128-CBC with the key as its IV; the key is not stored anywhere: `eabig.key_for` finds it in `main`'s code (the 8-byte key name compared with a 64-bit literal in `Fifa::AssetStreamCryptoKeyProvider::GetKey`, then the `adrp` / `add` / `ldp` of the key) and keeps the candidate whose decryption matches the SHA-256 of the first 32 plaintext bytes that the EASF header carries.
- **Resolved: players and crowd drew black in matches.** `sh_irradiance_prefilter.cs` (the compute shader that bakes the spherical-harmonic lighting) was missing from the map: SDK 3.4's GLSLC writes its control section 0x180 bytes longer than its +0x20 says, and the bytes after +0x20's length (float constants) passed as headerless compute code. `glslc_shaders` takes the output's own section header there, by the rule Trails in the Sky 2nd Chapter added for the same layout, widened: Trails' real code starts with the compute header (`CS_MAGIC`), FIFA's with a scheduling word, so a header control section longer than the rule's and starting with it wins too when the header's code starts with a scheduling word (`sched_word`; the rule's code area then begins inside the control section). 1 of the 189 outputs changes.
- **Resolved: the menus had no text.** The glyph cache (`EA::Text::GlyphCache_RNA`, a 1024x1024 R8 linear texture) is filled first by a GPU copy and then by the CPU through `nvnMemoryPoolMap`; the GPU copy ended the image's tracking of CPU writes. Fixed generally since: a GPU-written linear texture follows the CPU's writes once its copy-back into the storage has run on the GPU (`vka_wbfollow.h`, `DM_VK_WB_FOLLOW`; found on Mario Tennis Fever's glyph cache). FIFA's own fix of the same case (`wb_cpu`) was dropped at the rebase; the menus' text is to be checked again on the phone with the general one.
- **Resolved: close-up kits and faces red with alpha 0, orange shadows.** The runtime texture compressors (`compress_bc1.cs`, `compress_bc3.cs`, `SportsRNA::Utility::DXTBatchJob`) load the composited RGBA8 textures with `SULD.D .B32` (raw 32-bit texels, declared `r32ui`); the host gave them an `R8G8B8A8_UINT` view, so each load returned only the red byte. A shader image of an integer class over a 4-byte texture of another class is viewed as `R32_UINT` / `R32_SINT` for this game (profile key `image_raw32 on`, [dm/games/README.md](../README.md); `vka_raw32.h`; `DM_VK_RAW32=0`: as before). Off for every other game until more of them have run with it.

## Open

- **Replays, celebrations, training, the goalkeeper camera and similar close-up views: the players are not visible, on Qualcomm's system driver only** (Turnip T30 shows them). They are drawn (with the pitch's pixel shaders skipped through `DM_VK_SKIP_FS`, every player shows, textured), but the pitch, drawn after them in the next render pass on the same targets with the same less-or-equal test, covers them. In a normal match the passes come in the same order and the players show, so the players' depth in these camera modes is wrong or lost there. Turnip draws the same commands right, so this looks like the system driver's handling of these passes (not yet found which).
- Kit preview: the faces draw black on Qualcomm's system driver (right on Turnip T30; not looked into).
- `nvnCommandBufferSetSubpixelPrecisionBias` and `nvnQueueGetTotal*MemoryUsed` / `nvnQueueResetMemoryUsageCounts` are unimplemented (red lines, no visible effect).
- The memory layout is the survey's guess (`mem_used` from the size of the Android rewrite, as its line in `game.tsv` says); no peak measured.
