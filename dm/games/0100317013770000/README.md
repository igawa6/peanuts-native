# Mario + Rabbids Sparks of Hope (`0100317013770000`)

Update 1.6.2225577 (v393216) over the base game, SDK 13.3.5, Ubisoft's Snowdrop engine on NVN, with Havok and Wwise. The ExeFS loads `main` and `sdk`; the seven supplied DLC NSPs are indices 1–7. **Mac: playable opening exploration, including a saved campaign reload. iOS remains unvalidated.**

## Memory

- The NPDM declares 16 MB of system resource. `nninitStartup` (`main+0x4d1300`) sets a 10 MB heap; the engine takes its memory through address regions and commits pages on demand.
- **Resolved: startup reservation failure.** [Separate virtual ranges in Snowdrop's page allocator](../../../docs/reference/memory.md#separate-virtual-ranges-in-snowdrops-page-allocator). The constructor (`main+0x1642b8`) originally gives each pool 4 GB, alongside a 1.1875 MB metadata region. `patches.py` reserves 3 GB with 2 GB for large allocations, 512 MB for 512 KB pages and 512 MB for 64 KB pages. Both uses of the combined size change together (`+0x1642fc`, `+0x164308`); `+0x1642c8` initializes the slab-size fields, and `+0x164300` / `+0x16430c` override the large range. SDK build `43211771ed39e7fcef03d88e27091831` also needs its node area cut to 62 MB (`+0x37c140`, `+0x37c1dc`) and large regions aligned to 32 MB (`+0x37c33c`). With the node cut alone, the 3 GB reservation still fails.
- **Resolved: large allocations crossed the class boundary.** The large allocator's initialization (`main+0x168310`) separately takes a maximum 64 KB page count in `w5`, stored at object `+8`. `patches.py` changes it from 65536 to 32768 (`+0x164338`) to match the 2 GB range. The initial outer-boundary cut alone left this child allocator at its original 4 GB capacity: while loading the first campaign it returned a 12 MB compressed-file buffer exactly at the 512 KB pool's base. `free` routed that pointer to slab handling and interpreted compressed payload as its owner (`main+0x1668dc`). The corrected rewrite loads and reloads the opening campaign. The fixed 1 MB large-allocation metadata reserve (`+0x168308`) still holds more nodes than the reduced capacity needs.
- **Resolved: UI contexts without address space (GitHub issue #483).** Shaking the overalls bush in “An \"Overall\" Nice Day”, or loading a save from the first planet, wrote to `0x78` at `main+0x2c534a8` (`lr=main+0x2c53484`): the 136-byte entry array of a UI node context (`Moria::Services::UI::Shared::Nodes::Context`, built at `main+0x2c4a228`) had no base. Each context reserves 576 KB and 256 KB of address space and never checks the reservation. Measured with a 64 GB alias region (`DM_ALIAS_SIZE=0x1000000000`, `DM_REGIONS`) in the opening quest: the node area (62 MB), a 1.06 GB pool of 4,194,304 272-byte slots (`main+0x94364`), Snowdrop's 3 GB, a 152.6 MB pool of 16-byte entries (`main+0x14dbd4`) and 147 contexts (119.5 MB) end at +4.515 GB, past the profile's 4.375 GB; 150 contexts after the overalls. On the profile's layout the regions reach +4.375 GB, only 110 of the 147 contexts got their 576 KB range, and the overalls bush crashes as in the issue. The 1.06 GB pool had nothing committed: only the memory system's startup (`main+0x94260`) and its teardown (`main+0x94214`) name it or the default-pool slot it fills. `patches.py` gives it 65,536 slots (17 MB, `+0x94354`), which leaves about 1 GB for the contexts and later regions. The same route then picks up the overalls without a crash.
- **Current measurements; later capacity open.** In the reloaded opening quest, 64 KB pages held 291.9 MB active / 296.3 MB of bump space, 512 KB pages held 156 MB / 213.5 MB, and large allocations held 1007.4 MB within a 1280 MB managed span (2048 MB capacity). The shortage flag was zero. The slab allocators (`main+0x164aa8`, `+0x1649a8`) set the game's shortage flag (`+0x169f20`) at their derived ends and retain their original 4 GB reserve fallback. Later worlds and sustained battle play still need capacity testing.

## Files and shaders

- The merged RomFS holds 352 files under `moria/sdf/nx`: Snowdrop `.sdfdata` slices, a `.sdftoc`, a `.sdfver` and a `.mapping`. DLC can supply further slices and shaders.
- **Resolved: no shaders found by the split.** The shaders are compressed records in `BERG` archives: [Shader records in Snowdrop SDF data slices](../../../docs/reference/shaders.md#shader-records-in-snowdrop-sdf-data-slices). The split reads every supplied RomFS, including DLC.
- The registered shader union contains 23,280 stages: 20,400 vertex, 2,599 fragment and 281 compute. Base plus update contributes 18,459; DLC indices 5, 6 and 7 add 632, 2,193 and 1,996 respectively. Indices 1–4 add no unique shaders. Every stage compiles for the Mac, including the pulling and shadow-input variants. A different installed DLC set gets shader tables derived from that set while retaining the registered module fixes.

## Rendering

- **Resolved: compute image writes discarded.** [Image bindings supply shader-write intent](../../../docs/reference/nvn-objects.md#image-bindings-supply-shader-write-intent). The game registers its depth-conversion output through `RegisterTexture` with only `COMPRESSIBLE`; the writable image binding now upgrades its backing before dispatch. The final Mac run uses the real image and renders the lit castle grounds.
- **Current: inactive menu placeholder warnings.** Fragment shaders `184b0b673101a2da`, `4143b4dfc3115f89`, `a5c80eb8e6380096`, `0ca739a46129f292` and `ad34a496c970dff1` declare a 3D texture in slot 3, but some menu draws bind the game's 2D placeholder (texture ID 262). All ten sampling sites are guarded by fragment CB0 float `+0x180` being nonzero or NaN. A capture spanning frames 878–909 found 148 placeholder draws, each with this float exactly zero, and 42 draws with a real 3D texture, each with 150.0. No overlapping deferred uniform updates occurred. The type warning describes an unused binding on this captured route; no shader or binding workaround was added.

## Mac testing

Tested on 2026-10-27 with the registered update and all seven supplied DLC packages. Title and campaign menus, creating File 1, the opening Peach dialogue, walking around the castle grounds, camera movement and collecting coins work. Reloading File 1 returns to the active “An \"Overall\" Nice Day” quest. The final validation uses all 23,280 stamped Mac shader libraries and their generated uniform tables; the earlier image-write failure is gone and no shader libraries are missing on this route.

To drive the Mac test, set `DM_GAME=0100317013770000`, use the rewritten `patched_v393216` modules, the merged update RomFS, the shader output's Mac directory and `DM_AOC_DIR=<build>/aoc`. From a clean boot, `DM_KEYS=40:A,44:A,48:A,52:A` passes the title, campaign menu, File 1 and Continue Journey. Advance the first dialogue with A when starting a new file; use the left stick to walk and the right stick for the camera. Keep `DM_SAVE` in the NSP work folder. Give each boot a fresh `DM_CTL` file so old inputs and diagnostic settings do not replay.

Game files, logs and analysis stay beside the NSPs, in `0100317013770000_build` and `0100317013770000-work`.

## Android (Peanuts Native)

**Status: Android has not been tested at this point.** The profile is the Mac/iOS one with one Android-side choice; nothing below is measured on a device yet.

- **Dump:** update 1.6.2225577 (v393216) over the base game and all seven DLC (indices 1-7), imported into one `.nup`. The main and sdk build IDs equal the registered ones, and `pack_android.py` applies the seven `main` cuts of `patches.py` (original bytes checked) and five function-matched `sdk` cuts (node area 62 MB, region alignment).
- **Keys chosen:** `op_mode handheld` (the Retroid Pocket Nova is a handheld; docked draws the coins with wrong colours, issue #483; `DM_OPMODE=1` is the docked A/B). `mem_used` stays unset and the shader tables and `shader_note` are unchanged. `tex_flush_upload` and `tex_dirty_upload` are off, as validated on the Mac.
- **`alias_sync on`** (Android, [`dm/games/README.md`](../README.md)): the ambient chain of the lit shaders packs 4 R8 texels in one RGBA8 texel (640x360 R8 and 160x360 RGBA8, one storage, 640-byte rows). The replay makes one image for each shape, so the R8 occlusion input read 0 and shade drew near-black on the Retroid Pocket Nova (Turnip T30); with the copy, near-black in the shade band went from 48-78 % to 0.0-0.1 % and the frame rate did not change. The log says `alias sync: on (profile)`; `DM_VK_ALIAS_SYNC=0` is the A/B. The sunlit areas are about 13 % brighter with it on (an occlusion term now applied; not judged against the Switch).
- **`tbuf_store_copy on`** (Android, [Storage texel buffers at an unaligned offset](../../../docs/reference/rendering.md#storage-texel-buffers-at-an-unaligned-offset-android)): compute stores into storage texel buffers at an offset the device cannot view (the `[RED]` unaligned texel buffer lines, offset 0xff20, alignment 64) go through an aligned scratch copy. `DM_VK_TBUF_STORE_COPY=0` turns it off for an A/B run. Checked on the Retroid Pocket Nova (Turnip T30) in a current save, a new game and a battle: 0 refused copies, 0 `[RED]` lines, and the shade renders correctly. With `DM_VK_TBUF_STORE_COPY=0` the `[RED]` lines come back.
- **Frame rate (`game_args -fpslimit 60`, `fps_limit 30`):** the game limits itself to 30 fps (present interval 2). `-fpslimit 60` is the game's own command-line argument (parsed at `main+0x281e14..0x281e90`, found in the earlier port of this game): with it the game presents at interval 1 and its own clock runs at 1/60 s, so the host's frame limiter, not the game, sets the rate. `fps_limit 30` keeps the default at the game's own 30 fps; the launcher's Frame rate slider (20, 30, 40, 45, 60; 30 by default) and the in-game panel can raise it live. Game owned (the game's 60 with no host limiter) is no longer offered for this title; a stored Game owned reads as 30. Never `-nofpslimit` (black 3D in the earlier port) and no `-preset`. `fps_limit_min` and `fps_limit_present` are not set. In the earlier port the game's speed was equal at 30, 43 and 60 fps in a walk probe; not measured with this host, and not yet run on a device. The log should say `game arguments from the game profile: -fpslimit 60` and `main: frame limit 30 fps (game profile fps_limit)`.
- **Graphics settings (`window_words`, `view_scale_words`, `upscale_pass`; replaces the old `DM_MRSOH_3D_FULL` option, which was removed):** the game builds its window size and its 3D scale from movz / movk immediates in `main` (build `5b76a43b...`), which the loader rewrites at load from `DM_WINDOW_SIZE` and `DM_SCENE_PCT` after checking every site against the word the profile lists (all sites of a key or none; a mismatch gives one `[RED]` line and the game's own value). The game's own values are what the profile lists, so with nothing chosen nothing is written. Measured on the Retroid Pocket Nova (a probe build): the 3D picture is the scale times the window, rounded to even (90 % of 1280x720 is 1152x648, 80 % 1024x576, 40 % 512x288, 5/6 of 1080p 1600x900); the ambient pair of the alias sync is 0.5 x the window (640x360 R8 / 160x360 RGBA8 at 720p, 960x540 at 1080p) whatever the 3D scale is; the alias sync fired and the shade stayed lit at every size; 1080p ran at 30 fps (GPU about 8 ms, PSS 2.2 GB). `DM_OPMODE=1` (docked) only widens the camera: the window and the 3D scale are the same. The launcher rows (Game settings > Performance > Picture; the in-game panel's Display tab) are:
  - **Output resolution:** Native (the largest of 1920x1080 / 1280x720 that fits the display: 1280x720 on the Nova, letterboxed) or the other size; always sends `DM_WINDOW_SIZE`. A true 4:3 full-panel window is not offered. Restart.
  - **Internal resolution:** 40 % to 100 % in steps of 10 (`DM_SCENE_PCT`), or Game default (the default: the game's 5/6, nothing sent). A stored `DM_MRSOH_3D_FULL` choice becomes 100 %. Restart.
  - **Internal upscaler:** Bilinear (the game's own stretch, the default), FSR 1 or SGSR 1 with a sharpness slider (`DM_VK_CUPSCALE` 1 / 2 / 4, `DM_VK_CUPSCALE_SHARP`). The hook upscales the 3D picture from the Internal resolution to the Output resolution inside the game's composite pass (profile `upscale_pass`: the composite's vertex and pixel shader and the binding of the 3D picture, read from the shader library); the HUD is drawn at the output size either way. At 100 % there is nothing to upscale, so the three choices look the same. FSR 1 / SGSR 1 add compute passes; the expected cost is about 0.3-1 ms of GPU at 720p (inferred, to be measured; an older fragment version of this idea measured +2.1 ms at 0.6 on another host). Live from the in-game panel.
  - **Graphics quality:** Handheld (the default, `op_mode handheld`) or Docked (`DM_OPMODE`), unlocked for this title and decoupled from the resolution. Restart.
  - **Frame rate:** a slider, 20 / 30 / 40 / 45 / 60, default 30, no Game owned (see the frame-rate bullet above). The sliders have no end captions; on the in-game panel Internal resolution shows `Applies on next start`.
  Not yet tested on a device: the new code. The first launch should log `window: <w>x<h> (window_words, 4 words)` and, with an Internal resolution chosen, `scene scale: <p> % (view_scale_words, 4 words)`, and no `[RED]`; the old `DM_MRSOH_3D_FULL` host option is gone, so `main: selected option code patches` must not appear. The host's Resolution scale and the output-to-screen Upscaler (NDSR) rows do not help this title on the Nova (the output window is already 1280x720; the G-buffer fetch demotes the scale to 1x).
- **Memory layout (Android only):** `patches.py` now cuts Snowdrop's ranges to 4 GB in total (2 GB large allocations, 1 GB for 512 KB pages, 1 GB for 64 KB pages; `+0x1642c8` 1 GB, `+0x1642fc` and `+0x164308` 4 GB), and `game.tsv` carries `mem_reserve 0x180000000` (6 GB block) and `mem_alias 0x158000000` (5.375 GB; stack 256 MB and the 128 MB heap are unchanged). Both memory rows change together: `mem_init_once` needs the alias to be at most the reservation minus 256 MB. Reason: on the Retroid Pocket Nova two battle loads aborted (`nn::diag` at `sdk+0x16ba48`) after the 512 MB 64 KB range filled; the slab source then asks `AllocateAddressRegion(4 GB)` in a loop that cannot succeed in the alias region, each refusal leaks an SDK node and the 62 MB node area runs out. The size fields, the free path and the one size getter (`+0x166da0`) derive their values at run time (disassembly of the whole allocator module), so 1 GB per range is a move toward the game's own 4 GB. Expected boot lines: `guest AS 0x4000000000 +0x180000000 ... alias 0x4010000000 stack 0x4178000000` and `address region 4.00 GB at alias +0.08 GB, returning to main+0x12300c`. **iOS:** a single reservation is capped at 6 GB and 5 GB is the most proven on a phone, so this 6 GB layout is not meant for iOS (the Mac/iOS profile was 5 GB / 4.375 GB with the 3 GB cut). The host also logs `[mem] address region refused (inferred)` (1st, 10th, 100th ... refusal; `dm/host/hle_svc.c`) when a region request is not followed by a success on the same thread. Whether 1 GB for the 64 KB range is enough for later worlds is not known; the next step would be three 2 GB ranges. Checked on the Retroid Pocket Nova (Turnip T30): boot, battle entries and normal play, with no battle-load abort.
- **Shaders:** the registered 23,280 stages (20,400 vertex, 2,599 fragment, 281 compute) are used as they are.
- **Test app:** the game is not in `peanuts/games.tsv`, so a test build needs `-PnxGames=0100317013770000`.
- **Host guard (stopgap):** `nvnSyncWait`, `nvnQueueWaitSync` and `nvnQueueFenceSync` pass a sync pointer below 0x10000 with a one-time `[RED]` line (`dm/gfx/nvn/hle_nvn.c`), after a NULL sync seen after battles in an earlier port of this game. The guest cause is not known.

  - Later worlds have not been run on any platform.

  - The sync guard above: whether it is ever hit.

### Prewarm seed

A prewarm seed is recommended for this game: the first battle load on an empty pipeline cache can hang the GPU on Turnip; with a seed made from a play-through, 4 of 4 cold battle loads had no hang. The maintainer builds the seed; the pipeline key list from our runs is available on request.
