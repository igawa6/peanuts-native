# Demon Throttle

The base title ID is `01001DA015650000`; the dump folder carries no control data, so the display version is unknown and the pack is the base one (its file name says `v0`). SDK **13.3.0** (`nnSdk-13_3_0`, `NintendoSDK_NVN-13_3_0`, `NintendoSDK_OpenGL-13_3_0`). A **GameMaker Studio 2** game like [Well Dweller](../0100217023F6C000/README.md): the RomFS holds the runner's data file (`game.win`, `audiogroup1.dat`, `options.ini` with `[LLVM-Switch]`), its pictures and its CSVs. `main` draws through **EGL and OpenGL**; the NVN imports it names belong to the movie path (`subsdk1`), and `subsdk0` (NintendoSDK_OpenGL) is not loaded — the host's GL front answers the game's GL directly. On the Mac path that class renders through `hle_gl.m`; this is the first title to reach the Android front.

## Graphics (Android)

The title starts on the AYN Thor: its EGL and GL calls run on the host's driver context (Adreno 740, `OpenGL ES 3.2 V@0676.53`), its window comes from the Vulkan replay's handover, and its frames are presented by the front itself — the whole mechanism is [the GL front on Android](../../../docs/reference/rendering.md#on-android-a-gl-title-draws-into-the-launchers-window-its-own-front-presents). Its title screen fills the window: read back from the game's own framebuffer at the window's full 1920x1080, the lit bounds are `0,0..1919,…` — the game sizes its views by `eglQuerySurface`, which answers the real buffer size. The draws are the runner's: `glDrawArrays` of at most 36 vertices with client-memory arrays, thousands of `glClear`s a second, the same shape the Mac path recorded for Well Dweller ([Draws from client memory](../../../docs/reference/rendering.md#draws-from-client-memory)). No shader tables are needed on Android: the front compiles the game's GLSL through the driver's own compiler, which accepts all of it.

## Frame rate

The game free-runs at 800-1800 swaps a second at its title screen — the frame path has headroom, and the pacing is all host-side. What the front does with a panel (59.9 Hz mode at start, switched to 120 Hz by the system a second later despite the window's ask of 60 FIXED_SOURCE), which swap intervals this driver takes and which it refuses, and the measured grid mismatch are [the presenter and its pacer](../../../docs/reference/rendering.md#a-gl-title-presents-at-the-panels-rate-and-runs-twice-as-fast-as-it-was-made). Held at 60.0 frames a second by the host pacer, the launcher's on-pace figure reads **94-97%**: the frames are aimed at the panel's named slots, which are not the grid the panel runs on (its own interval figure is exact 120.000 Hz; the same Thor measures 118.52 Hz, [frame-rate.md](../../../docs/reference/frame-rate.md)). **Open**: aiming at a measured period, the way `vka_panel.h` does for the Vulkan path, and showing whether the display timestamps complete when a pending frame is asked again instead of once.

The player played the first level to check the game's speed feel and the frame pacing's smoothness: the speed reads right; at that figure the player judges the picture "still not smooth".
- Turnip was not run on this title: the GL front draws through the system EGL, and Turnip does not take those calls; the only path a Turnip would change here is the window-form query the replay answers.
